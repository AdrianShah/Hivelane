1. Server (server/main.py)





FastAPI app with a single /ws WebSocket endpoint (single global room, per non-goals).



In-memory state:





connections: dict[str, WebSocket] — user_id → socket



file_activity: dict[str, dict] — file_path → {user_id, diff, prompt, timestamp} (populated now, consumed later by conflict detection in step 7)



Connection flow:





Accept socket, wait for a join message containing raw display name (need to add this as an implicit first message since the spec's activity schema has no explicit join event — client sends {"type": "join", "name": "<raw>"} as the first message after connecting).



Run sanitize_name(); on ValueError, send name_rejected with the reason and close or allow retry on the same socket (retry on same socket to avoid reconnect overhead — watcher re-prompts locally per spec step 4).



Check name in connections; if taken, send name_rejected with "Name taken".



On success, register connection, broadcast user_joined to all (including new client), send nothing else special back (new client infers success by receiving its own user_joined).



Message loop per connected client:





Receive JSON, validate against activity schema (Pydantic).



Update file_activity dict for each changed file (timestamp-stamped) — conflict-detection consumption deferred.



For step 1-3 (no Gemini yet), build activity_update by directly echoing the incoming payload plus a placeholder caption (e.g. None or a simple deterministic string like "{user_id} updated {n} file(s)") so the frontend has something to render immediately; swap in the real Gemini call in step 4 without changing the message shape.



Broadcast activity_update to all connected clients.



Disconnect handling: on WebSocketDisconnect, remove from connections, broadcast user_left.



models.py defines Pydantic models for activity, activity_update, conflict_alert, user_joined, user_left, name_rejected, and the new join message — single source of truth so the eventual Gemini-wiring step doesn't touch message shapes.



sanitize.py implements sanitize_name() exactly as specified (regex strip to [a-z0-9_-], length 1-20, blocklist substring check).



requirements.txt: fastapi, uvicorn[standard], websockets, pydantic, python-dotenv (for GEMINI_API_KEY later), google-genai (added now so step 4 doesn't need a fresh install, but unused until then).



Run via uvicorn server.main:app --reload --port 8000; note in README that ngrok http 8000 tunnels it.



CORS: enable permissive CORS middleware (frontend dev server on a different port/origin, and ngrok URL will differ again).

2. Watcher (watcher/watcher.py)





CLI entrypoint takes --path (project folder to watch) and --server (ws:// or wss:// URL) as args (argparse), defaults to . and ws://localhost:8000/ws.



Prompts for display name via input(), pre-validates client-side with a local copy of the sanitize regex/length rule (best-effort UX per spec — server remains authoritative).



Connects via websockets client, sends {"type": "join", "name": raw_name}, awaits response:





If name_rejected, print reason, re-prompt, retry (same connection).



If user_joined for self, proceed to watch phase.



File watching:





watchdog.observers.Observer + a FileSystemEventHandler recursively watching --path, ignoring common noise dirs (.git, node_modules, __pycache__, .venv) via a path filter.



On each modify/create event: compute a diff for that file. Simplest viable approach for the time-box: keep an in-memory last_seen_content: dict[file_path, str] snapshot per file; on event, read new content, compute unified diff via Python's difflib.unified_diff against the last snapshot (empty string if first time seen), update snapshot. This avoids depending on git and works even in non-git folders.



Store/refresh entry in a local pending-batch dict keyed by relative file_path, storing latest diff.



Debounce: a threading.Timer (or asyncio task) reset on every event; fires after 1.5s of inactivity, flushing the batch as one activity message (prompt: null for now — prompt capture is step 6) and clearing local state.



Relative path computation: os.path.relpath(abs_path, watched_root) with forward slashes normalized, per spec requirement.



requirements.txt: watchdog, websockets.



Runs as a blocking asyncio event loop (asyncio.run(main())) combining the watchdog observer thread with an async WebSocket send queue (watchdog callbacks run on their own thread, so use asyncio.run_coroutine_threadsafe or a thread-safe queue bridged into the asyncio loop).

3. Frontend (frontend/)





Scaffold with Vite React-TS template (npm create vite@latest frontend -- --template react-ts).



types.ts: TypeScript interfaces mirroring every server message type from the schema (ActivityUpdate, ConflictAlert, UserJoined, UserLeft, NameRejected).



App.tsx:





Opens a WebSocket to the server (URL configurable via .env / Vite env var, defaults to ws://localhost:8000/ws, overridable for the ngrok demo URL).



Sends nothing (frontend is a pure spectator, doesn't join as a named user — it just listens; confirm this matches spec: spec's user flow describes only watcher clients joining with names, frontend is read-only spectator, so it connects but never sends a join — need a way for server to allow spectator connections without requiring a name. Design decision needed: add a role: "spectator" on the join message, or have the server treat any socket that never sends join before an activity as spectator-only and skip auth. Simplest: frontend sends {"type": "join", "name": null, "role": "spectator"} and server registers it in a separate spectators: set[WebSocket] that receives broadcasts but isn't part of the named-user room and isn't subject to name collision checks.)



Maintains users: Record<string, LaneState> state, updated on user_joined (add empty lane), user_left (remove lane), activity_update (update that user's lane with latest caption + changes).



Renders a responsive CSS grid of <Lane> components (CSS grid with auto-fill/minmax so it reflows for 2-4 users without hardcoding column count).



Lane.tsx: shows username, caption (bold/prominent), list of changed file paths with an expand/collapse (<details>/<summary> or simple toggle state) to reveal the diff text — collapsed by default.



ConflictBanner.tsx: stub component accepting a conflict list prop, not yet wired to real data (returns null / renders nothing meaningful until step 8) — included now so the layout slot exists.



Basic clean styling (CSS modules or plain CSS) — dark-ish dashboard look, not deeply polished per non-goals.

Server/Spectator connection design (clarifying addition to spec)

The original spec's join-less flow only covers named watcher clients. To let the frontend connect as a passive viewer without a name, the plan adds one small, backward-compatible extension:





New client message (not in original spec, additive): {"type": "join", "name": null} → server treats name == null as a spectator: added to a spectators set, receives all broadcasts, never appears in connections, immune to name collision/blocklist checks, and does not trigger user_joined/user_left broadcasts for itself.



All existing named-client behavior (watchers) is unchanged.
